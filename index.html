Approach

Fix causes, not symptoms

A bigger pool, a longer timeout and a retry loop will quieten almost any concurrency bug. None of them remove it.

On my own project, transactions were deadlocking while the connection pool starved. Rather than tuning the numbers, every transaction now takes its row locks in one consistent order, which makes a lock cycle impossible, and requests are batched behind a debounce so the pool is never flooded. One invariant at the source instead of patches at every call site. That is the habit I bring to production work.
